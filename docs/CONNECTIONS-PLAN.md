# توصيلات المشروع — تنفيذ OBS-145

بدأ التنفيذ في 2026-09-08 على `feat/project-connections` من الإصدار `2.16.21`.
تعديلات القرار السابقة في OBS-144..148 وخطتي برو والجوال محفوظة.

## الخطة

1. نواة مجانية: ملكية بمسار المشروع الحقيقي، تخزين مشفر يرفض الحفظ المكشوف، حساب ومورد لكل خدمة، وصلاحيات قراءة وكتابة مع إبطال الطلبات القديمة.
2. GitHub: التحقق من الحساب واختيار مستودع واختبار قراءة ثم قراءة الملفات والقضايا وإنشاء قضية بإذن مستقل.
3. Netlify: موقع ونشراته وتشغيل بناء بإذن؛ Supabase: مشروع قاعدة بيانات وقراءة بنيته باستعلام ثابت عبر مسار القراءة فقط.
4. تطوير `/موصلات` القائمة مع إبقاء إعدادات MCP الخاصة بالمحرك ظاهرة كقسم مستقل.
5. اختبارات النواة والنقل ومسار المحرك، وعضة لكل حارس جديد، وقياس العربية عند عرضين، ثم نسخة مبنية للقبول البشري.

## حدود الدفعة

- إعداد الاتصال ونجاح المصادقة واختبار API واستخدام المحرك حقائق منفصلة.
- كل نداء يفحص المشروع والمورد والصلاحيات ونسخة الاتصال؛ الفصل وإعادة المصادقة يبطلان موافقات ونتائج النسخة السابقة. لا وعد بالتراجع عن أثر أرسل للخدمة.
- الرموز داخل العملية الرئيسية، خارج المشروع والمحادثة والسجلات ووسائط المحرك. لا توريث لحسابات CLI أو MCP أو البيئة، ولا أداة HTTP عامة أو SQL حر.
- البداية تستخدم رمز وصول شخصياً يدخله المستخدم في حقل سري باللوحة، مع فتح صفحة الخدمة داخل المعاينة. هذا اتصال برمز شخصي وليس اكتمال OAuth.
- GitHub Device Flow يحتاج GitHub App وclient_id مملوكاً لسطر، بلا client_secret. Netlify يشترط OAuth للتكامل العام؛ دفعة الرمز الشخصي لا تنشر كتسجيل دخول عام مكتمل. Supabase Management OAuth يحتاج سراً تطبيقياً، ومصادقة MCP المستضاف لا تساوى برمز API.
- الأتمتة والجوال ومبدل المشاريع خارج الدفعة. لا تبعية جديدة ولا تغيير إصدار أو commit.

## معايير التحقق المكتوبة قبل التنفيذ

- قراءة المورد المسموح تنجح، وغيره يرفض قبل HTTP ولو كان عاماً.
- المشروع الثاني لا يرى حساب الأول أو موارده أو صلاحياته.
- غياب التشفير وفشله لا يكتبان نصاً صريحاً ولا يستبدلان اتصالاً سليماً.
- 401 يعني إعادة مصادقة، و403 يظهر نقص الوصول دون ادعاء انتهاء المصادقة.
- الفصل أثناء انتظار الإذن يمنع إرسال الفعل، والنتيجة المتأخرة لا تعيد الاتصال.
- الأفعال المؤثرة تحتاج إذناً حالياً مرتبطاً بالمورد، حتى لو كانت للمحرك منحة سابقة.
- القبول البشري: المستخدم يربط مورداً تجريبياً ويفحص الحساب والمورد، يختبره، يستعمله من المحادثة، يفصله ويعيد الطلب. تفصل معايير الصواب والفشل قبل تسليم النسخة.

## النتائج الفعلية

- نُفّذت نواة المشروع ودفعة الرمز الشخصي للخدمات الثلاث داخل `/موصلات` القائمة، بلا تبعية جديدة.
- الحراس تشغّل كود الإنتاج: نواة التخزين والتنفيذ، IPC الموثوق، HTTP MCP، محولات الخدمات، وواجهة Electron. نجحت الخدمات 12/12 والواجهة 8/8؛ إيصالات العضّات الحرفية في [وثيقة الأدلة](CONNECTIONS-TEST-EVIDENCE.md).
- Codex المثبت `0.153.4` مع `gpt-5.6-sol`: نجحت المراحل الست للمسبار وانتهى برمز 0 والتنظيف مكتمل. يثبت القراءة المسموحة، ومنع المورد الآخر، و401، والفصل، وعزل المشروع، وإذن الكتابة المرفوض رغم وضع تجاوز أذونات المحرك. الشبكة محقونة عند fetch في محول GitHub الإنتاجي، والتشفير AES-GCM اصطناعي؛ ليس هذا حساب GitHub حياً ولا فحص DPAPI. التقرير في `dist/connections-engine-probe.json`.
- دمج الأدوات موجود في Claude SDK وCodex وKimi Code والمحوّلات الثلاثة التي تدعم استدعاء الأدوات. الاستخدام بالنموذج المثبت قيس في Codex فقط؛ بقية المحركات ليست شهادة استخدام حي.
- `browser_readability` على المشهد المحلي أعطى صفر مخالفات عند المقاسين الفعليين 390×650 و839×650؛ طلب 1000 حُدّ بعرض لوحة المعاينة. قياس النواة التشخيصي في Electron غطّى الثيمين عند 390 و1000: 23 عنصراً في كل عينة، وجميع العدادات وunseen صفر، وtruncated=false. الأزرار والنصوص الأقصر من حد الأداة ليست ضمن هذا الادعاء؛ ليست هذه شهادة للواجهة كلها. التقرير واللقطات في `dist/connections-readability.json`.
- المحاولة الأولى للطقم الكامل انتهت 102/103 و`SUITE_EXIT=1`: تجاوز `term-longline` مهلة 240 ثانية بعد نجاح فحوصه. إعادة المجموعة وحدها نجحت 77 فحصاً برمز 0 خلال 18.5 ثانية. لا تمحو الإعادة فشل المحاولة الأولى ولا تثبت سببه؛ السجلان محفوظان.

## ما بقي قبل اعتماد الميزة كاملة

- إعداد تطبيقات المصادقة المملوكة لسطر ومسار OAuth المناسب لكل خدمة؛ دفعة PAT لا تحقق تسجيل الدخول العام المطلوب وحدها.
- استكمال قبول Netlify وSupabase والأذونات والفصل من الخطوات 11 إلى 14 عند عودة المالك للاختبارات، وتحديد تغطية المحركات والكتابة غير المثبتة. نتائج GitHub المثبتة محفوظة؛ اختبار إلغاء الرمز متجاوز وإعادة المصادقة التابعة له مؤجلة، ولا يغلقان كاجتياز. قيس DPAPI بنواة الحزمة المبنية ورمز اصطناعي معزول، والتقرير في وثيقة الأدلة.
- اكتملت معالجة القفل اليتيم للمخزن المحلي في Windows/Linux: قفل نظام ينتهي بموت العملية، مع علامة v2 ذرية تُسترد فقط بعد حيازته. قيس قتل المالك وتنافس عمليتين وحفظ القفل الحي. العلامات القديمة أو المجهولة أو التابعة لجهاز آخر تُحفظ، وUNC وباقي المنصات تبقى على القفل السابق. يتطلب المسار hard links؛ لا وعد لمخازن الشبكة أو المشاركة بين network namespaces. [القياس والعضّات](CONNECTIONS-RECOVERY-EVIDENCE.md).
- نجاح الفعل الخارجي لا يصبح فشلاً بسبب حفظ بيانات استعماله: يعاد نجاح مع usage_not_saved إذا بقي الاتصال مالكاً، وتبقى آخر بيانات استعمال محفوظة على حالها. إذا تبدل الاتصال بعد كتابة ناجحة تُحجب النتيجة القديمة ويُصرّح بأن الكتابة حدثت وبأنها غير قابلة للإعادة التلقائية.
- طلب المالك إكمال التحضير الآلي وجمع المتبقي في جلسة قبول واحدة. [قائمة القبول النهائية](acceptance-final-batch.md) تحفظ نتائج GitHub ونقطة الاستئناف السابقة؛ لا تعني بدء القبول أو اجتيازه.
