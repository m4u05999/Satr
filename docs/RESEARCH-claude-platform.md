# بحث: Claude Code / Agent SDK 2026 — وتغطية «سطر»

> **الحالة:** تقرير بحثي (Claude)، **نسخة مصحّحة** بعد تقييم كودكس المتبادل. قرين لتقرير OpenAI.
> **المصادر:** توثيق Anthropic الرسمي `code.claude.com` + **فحص فعلي للكود** (`app.js`, `agent.js`, `main.js`, `chat.js`, إصدار الـ CLI).
> **تصحيح منهجي:** النسخة الأولى استندت إلى صفحة `whats-new` (متمحورة حول CLI) وذاكرة `CLAUDE.md` دون فحص الكود، فوقعت أخطاء واقعية صحّحها التقييم المتبادل. الدرس: أي ادعاء عن الكود يُفحص فعلياً.

## 0. تمييز حاكم: CLI التفاعلي مقابل Agent SDK القابل للدمج

«سطر» يستعمل **Agent SDK** (`agent.js` عبر `query()`)، لا Claude Code CLI التفاعلي. لذا القدرات القابلة للدمج هي **عقد SDK البرمجي**، لا أوامر `/` في الطرفية. كثير ممّا في `whats-new` ميزات CLI (سطح منتج) لا تنقل مباشرةً. هذا الفصل هو أساس القرار.

## 1. النماذج — تصحيح جوهري

**الوضع الفعلي (مفحوص):** قائمة نماذج Claude في `src/ui/app.js:61` تستعمل **aliases**: `opus` / `sonnet` / `haiku` (+ `claude-fable-5`) — **لا معرّفات ثابتة** مثل `sonnet-4-6`. والـ alias يحلّ تلقائياً لأحدث نموذج متاح.

| النموذج | الجديد فيه | حالة «سطر» |
|---|---|---|
| **Claude Sonnet 5** (Week 27) | افتراضي جديد، سياق أصلي 1M، تفكير تكيّفي | ◐ **alias `sonnet` جاهز** — يحلّ إليه تلقائياً بشرطين |
| **Opus 4.8** (Week 22) | high effort افتراضياً | ✅ عبر alias `opus` |

**الحاجز الحقيقي (مفحوص):** الـ CLI المثبّت محلياً **2.1.175**، وSonnet 5 يحتاج **2.1.197+**. فالمشكلة **ليست القائمة** بل **إصدار الـ CLI**.

**الأولوية الصحيحة (لا hardcoding):**
- **فحص إصدار Claude Code وإرشاد المستخدم للتحديث** — **لا تحديث تلقائي**: «سطر» يعتمد المثبّت العالمي عمداً (بوابة `preflight` قائمة، تُوسَّع بفحص التوافق).
- انتقال alias `sonnet` → Sonnet 5 **مشروط** بإصدار CLI مؤهّل **وتوفّر النموذج للحساب/المزوّد** — التحديث وحده ليس ضماناً مطلقاً.

## 2. مصفوفة الميزات — أين نقف

### ✅ مدعوم (تكافؤ جيّد)
- `effort` بمستويات `low|medium|high|xhigh|max` (المرحلة 14.4)
- Skills `.agents`/`.claude` + تحميل تدريجي · اكتشاف أوامر `/` عبر `supportedCommands`
- MCP status/reconnect/toggle · context usage (`/سياق`) · compaction (`/ضغط`)
- Subagents مع عرض متداخل وبطاقات · Hooks (`PreToolUse`/`PostToolUse` للـ diff، Bash hooks)
- **التكلفة والمدة معروضتان** (`chat.js:752`: `total_cost_usd` + `duration_ms` + تراكم)
- **متصفح مدمج** — «سطر» **متقدّم على Claude Code** (in-app browser وصله Week 28؛ نملكه منذ الدفعة 5 بأدوات أعمق)

### ◐ جزئي
- **Subagents متداخلة**: نعرضها، لكن SDK صار يدعم عمقاً أكبر + تشغيلاً بالخلفية افتراضياً؛ عرضنا لا يغطّي الخلفية.
- **usage**: التكلفة الأساسية معروضة، لكن **`modelUsage` وتفصيل الرموز** (input/output/cached/reasoning حسب النموذج) غير مستغلّ — وهو متاح في رسالة `result` التي يمرّرها `agent.js:983`.
- **MCP**: ينقص `claude mcp login/logout` من الشِل (يحلّ قيد OAuth الموثّق في `/موصلات`).

### ❌ غائب — مرتّب حسب القابلية للدمج في SDK
| القدرة (عقد SDK) | ما هي | القيمة |
|---|---|---|
| **`permissionMode:'auto'`** | وضع أذونات أصلي: مصنّف Anthropic يمرّر الآمن ويحجب الخطر — **لا يُبنى يدوياً** | الأعلى أثراً على تجربة الاستخدام |
| **Structured Outputs** (`outputFormat` + JSON Schema) | مخرجات آلية مطابقة لمخطّط | reviewer/task-ledger/memory candidate |
| **`modelUsage` تفصيلي** | رموز حسب النموذج/النوع | شفافية استهلاك (توسيع لا إنشاء) |
| **`enableFileCheckpointing` + `rewindFiles()`** | نقاط استرجاع أصلية في SDK | أدقّ من معاملة `/rewind` كأمر CLI |
| **`resumeSessionAt`** | تفرّع من نقطة داخل الجلسة | استكشاف بدائل |
| **`fallbackModel`** | نموذج بديل عند الفشل | صمود — **تحفّظ:** النسخة المثبّتة قد تقبل **قيمة مفردة**؛ ادعاء «٣ مرتّبة» يحتاج تحقّق/ترقية قبل التوثيق |
| **Channels** | بثّ أحداث خلفية للنموذج | المقابل الأدقّ لفكرة Monitor (أعمق من bgprocs الذي يعرف PID فقط) |

## 3. الفجوات مرتّبة — ترتيب كودكس المصحّح (معتمد)

1. **فحص إصدار Claude Code وتوافق النماذج** — إبقاء aliases، تجنّب hardcoding، إرشاد تحديث لا تحديث تلقائي.
2. **`permissionMode:'auto'`** أصلياً + `PreToolUse` حارساً إلزامياً للعمليات غير القابلة للتفاوض. الدمج **ليس مجرّد تمرير قيمة**: يتطلب إضافة `'auto'` إلى `PERMISSION_MODES` في `main.js:214`، خيار الواجهة، ومعالجة `permission_denied` مرئياً. **خاصّ بمسار SDK فقط** (لا Codex ولا المحوّلات).
3. **توسيع عرض usage/`modelUsage`** من أحداث `result` الحالية — عائد عالٍ، جهد أدنى (التكلفة الأساسية موجودة).
4. **`fallbackModel` منقّى** + معالجة أحداث الفشل والرجوع (بعد التحقّق من مفرد/مصفوفة).
5. **checkpointing + structured outputs** للمسارات التي تحتاج نتائج آلية.
6. **تأجيل** Dynamic Workflows وMCP OAuth حتى تتّضح حدود SDK والأمان وتجربة المستخدم.

## 4. المحاور المشتركة مع تقرير OpenAI (توليف)

عابرة للمحرّكات (تخدم SDK + Codex + المحوّلات):
1. **توحيد `effort`** — SDK يمرّره؛ Codex والمحوّل يُسقطانه. عقد capability-aware واحد.
2. **توحيد `usage`/التكلفة** — Codex `null`، المحوّل يقدّر، SDK يعطي الحقيقي + `modelUsage`. عقد داخلي واحد `actual|estimate`.

خاصّ بمحرّك واحد (**لا** يُعمّم):
3. **الأذونات الذكية** — `permissionMode:'auto'` لـ **SDK وحده**؛ لمسار OpenAI نظير مختلف (إعدادات المزوّد). محورٌ مفاهيمي مشترك، بتنفيذ منفصل لكل محرّك.

## حدود موثّقة
- المعرّفات ومتطلّبات الإصدار تحتاج تحقّقاً حيّاً قبل الاعتماد (قاعدة ٨).
- ميزات مرتبطة بخطط/بنية سحابية (Artifacts، Routines، cloud ultrareview) قد لا تنقل لـ«سطر».
- `permissionMode:'auto'` يتطلب أن يبقى القرار الأمني الحاسم في `PreToolUse` (auto قد يتجاوز `canUseTool`)، وأن تبقى `run_in_terminal` وأدوات الكتابة خارج التمرير التلقائي.
