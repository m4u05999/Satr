# معمارية «سطر»: النواة (Community) + الطبقة الإضافية (Enterprise)

> وثيقة تأسيسية — تُقرأ قبل أي عمل يمسّ فصل النواة عن Enterprise أو إضافة قدرة مدفوعة.
> النموذج المعتمد: النواة في مستودع عام تحت FSL-1.1-MIT (‏source-available — قرار مالك
> 2026-08-06؛ ما نُشر حتى v2.10.0 كان MIT ويبقى)، ووحدات
> Enterprise في مستودع خاص مستقل
> يُضاف إلى الحزمة وقت بناء Enterprise فقط؛ لا ينشأ fork ولا نسخة ثانية من النواة. اكتمل
> الفصل الفعلي في 2026-07-17 بموافقة المالك.
> مصفوفة توزيع الميزات وقرارات الحدّ بين الإصدارين في `docs/EDITION-MATRIX.md`.

---

## 1) المبدأ الذهبي (لا يُخالَف)

**النواة منتج كامل يعمل وحده. Enterprise = النواة + وحدات إضافية تمتدّ فوقها عبر نقاط
ربط معرّفة — لا نسخة مكرّرة، لا فرع، لا سطر مزدوج.**

- ✅ إصلاح/ميزة نواة تُكتب **مرة واحدة** في `core/` ويستفيد منها الطرفان.
- ✅ `enterprise/` يحوي **الإضافي فقط** (ما لا وجود له في المجتمعية).
- ❌ يُمنع نسخ أي ملف نواة إلى `enterprise/`. إن احتجت تعديل سلوك نواة، أضِف **نقطة ربط**
  في النواة وامتدّ إليها من Enterprise (انظر §4).
- ❌ يُمنع أن يعتمد `core/` على `enterprise/` مباشرة (`require('../enterprise/...')` صريح).
  النواة تكتشف Enterprise عبر **مُحمِّل شرطي** فقط (§4.1)، وتعمل تماماً بدونه.

معيار القبول الدائم: **حذف مجلد `enterprise/` كلياً ⇒ يبقى «سطر» المجتمعي يعمل كاملاً بلا خطأ.**

## 2) بنية المستودع المستهدفة

النواة الحالية تبقى كما هي (لا نقل كبير الآن — انظر §5)؛ Enterprise يُضاف **بجانبها**:

```
satr/
├── electron/            ← النواة (Community) — العملية الرئيسية (FSL-1.1-MIT)
│   ├── main.js          (النافذة، توجيه المحرّكات، IPC)
│   ├── agent.js         (محرك Claude SDK — خاص)
│   ├── codex.js         (محرك Codex الأصيل عبر app-server)
│   ├── kimi.js          (محرك Kimi Code الأصيل عبر ACP)
│   ├── adapters/        (طبقة المحرّكات/المزوّدين: claude-cli, REST/OpenAI-compatible, Ollama)
│   ├── keys.js          (مخزن أسرار «سطر» — بذرة إعدادات Enterprise)
│   ├── features.js      (طبقة feature-flags + المُحمِّل الشرطي — تُضاف في §5)
│   └── … (term, diff, sessions, files, skills, agents, bgprocs, updater)
├── src/                 ← النواة (Community) — الواجهة (تُفكَّك تدريجياً لمكوّنات)
├── docs/                (PLAN.md, ARCHITECTURE.md, PHASE8-DESIGN.md)
└── build/               (community ⇐ يستثني enterprise/ ؛ enterprise ⇐ يضمّه)
```

المستودع الخاص `satr-enterprise` مستقل بجانب النواة، ويحتوي `satr-enterprise.json` وعقد
`register(seams)`. يحقنه البناء في الموضع المنطقي `enterprise/` داخل الحزمة فقط.

**ملاحظة تسمية**: لم نُنشئ `core/` كمجلد فيزيائي — النواة **هي** `electron/` + `src/`
الحاليان. هذا يتجنّب نقلاً ضخماً محفوفاً بالمخاطر؛ الحدّ المنطقي (نواة مقابل enterprise)
أهمّ من مجلد باسم `core/`. إن لزم لاحقاً لأسباب بناء، يُنقل بمرحلة مخصّصة.

- **النواة** (`electron/`, `src/`, `scripts/`, `build/`): **FSL-1.1-MIT** (‏source-available:
  الاستخدام حر لأي غرض عدا منتج منافس/إعادة بيع، وكل إصدار يصير MIT بعد سنتين — `LICENSE`).
  الإصدارات المنشورة حتى v2.10.0 صدرت MIT وتبقى كذلك.
- **مستودع `satr-enterprise` الخاص**: **رخصة تجارية مملوكة** (`LICENSE` منفصل، غير FSL).
  يُجمع مع النواة في مساحة بناء موثوقة عبر `SATR_ENTERPRISE_DIR` ولا يدخل Git العام.
- `README`/`CONTRIBUTING`: يوضّحان أن مساهمات المجتمع على النواة فقط (FSL-1.1-MIT)، وأن

> العامة هي المصدر الوحيد لكل السلوك المشترك.

## 4) نقاط الربط (Extension Points / Seams) — قلب المعمارية

Enterprise يمتدّ عبر هذه النقاط **حصراً**. كل نقطة موجودة أو مخطّطة في النواة:

### 4.1 المُحمِّل الشرطي (الأساس)
`electron/features.js` (يُضاف في §5) يحاول تحميل `enterprise/` إن وُجد:
```
let ee = null;
try { ee = require('../enterprise'); } catch (e) { /* بناء مجتمعي: لا Enterprise */ }
if (ee) ee.register(seams); // يمرّر نقاط الربط لـ Enterprise ليسجّل قدراته
```
النواة تعمل كاملة إن كان `ee === null`. هذا هو الضامن لمعيار §1.

### 4.2 سجلّ المزوّدين (موجود — `adapters/index.js`)
اليوم `REGISTRY = { cli, gemini }`. يصبح قابلاً للحقن:
`adapters.register(name, adapter)` — فتسجّل النواة مزوّداتها المجتمعية، ويمكن لـ Enterprise
إضافة مزوّدين مؤسسيين/خاصين (لا يحتاج Ollama الفردي إلى ترخيص).
دون لمس ملف النواة. **طبقة المزوّد العامة** (تعميم adapters) شرط لهذا.

### 4.3 مخزن الأسرار (موجود — `keys.js`)
`~/.satr/keys.json` اليوم. Enterprise يضيف: تشفير، تدوير مفاتيح، مصادر مؤسسية (Vault).
واجهة الإعدادات (نواة) تكتب المفاتيح؛ Enterprise يوسّع مصادرها.

### 4.4 feature-flags (يُضاف — `electron/features.js`)
`features.enabled('teams')` — النواة تُظهر/تُخفي قدرات بناءً عليها. الترخيص (Enterprise)
يفعّل الأعلام؛ في البناء المجتمعي كلها معطّلة (النواة لا تعرض قدرات Enterprise).

### 4.5 خطّافات IPC (نمط قائم في `main.js`)
Enterprise يسجّل معالجات IPC إضافية عبر `ee.registerIpc(channel, handler)` — لا تعديل
على معالجات النواة، فقط إضافة. القناة تلتزم `satr:ee:` حصراً وإلا رُفضت
(‏`electron/features.js`)، والمضيف الذي تُسجَّل عليه ليس `ipcMain` الخام بل **الغلاف
المحروس** `renderertrust.guardIpcMain(...)` الذي يحقنه `main.js` عبر
`features.init({ ipcMain })` — فتخضع قنوات `satr:ee:*` لتحقّق المرسِل والإطار نفسه الذي
تخضع له قنوات النواة. وغياب المضيف المحروس (اختبار Node بلا Electron) يُتجاهل بأمان بلا تسجيل.

### 4.6 نقاط امتداد الواجهة (بعد التفكيك — §5)
عند تحويل `src/index.html` إلى **Web Components**، تُعرَّف «فتحات» (slots/mount points)
تحقن فيها لوحات Enterprise (لوحة فرق، تدقيق، تكلفة) دون تعديل مكوّنات النواة.

## 5) خارطة التسليح (الشرط المسبق قبل أي فصل)

**لا يُنشأ `enterprise/` قبل وجود نقاط الربط** — وإلا نكرّر واجهة متراصّة. التسلسل
(مرحلة فرعية واحدة في الجلسة، نمط PLAN.md):

- **أ. طبقة المزوّد**: تعميم `adapters/` (Gemini REST ✅ أول لبنة) — `register()` + عقد موحّد.
- **ب. مركز الإعدادات/الأسرار**: واجهة إعدادات تكتب في `keys.js` (بدأ ✅) + مبدّل مزوّد/نموذج صف أول.
- **ج. `electron/features.js`**: feature-flags + المُحمِّل الشرطي (§4.1) — النواة تعمل بلا Enterprise.
- **د. تفكيك الواجهة تدريجياً**: لوحة واحدة/مكوّن واحد في كل جلسة من `index.html` إلى
  Web Components (صفر اعتماديات، CSP محفوظ) — تصبح نقاط امتداد الواجهة.
- **هـ. حينها فقط**: تُنشأ وحدات مؤسسية حقيقية في المستودع الخاص وتربط بالنقاط — بلا سطر
  مكرّر، مع فصل البناء (§6) و`LICENSE` التجارية.

## 6) فصل البناء (community مقابل enterprise)

- **بناء مجتمعي** (`npm run dist`): `files` في package.json **يستثني** `enterprise/**` (يُضاف
  `"!enterprise/**"`). الناتج = النواة وحدها، بلا أثر لكود Enterprise.
- **بناء Enterprise** (`npm run dist:ee`): يتطلب `SATR_ENTERPRISE_DIR` لمسار checkout خاص
  مطلق خارج Community. يتحقق `scripts/enterprise-source.js` من `contractVersion=1` ثم يضيفه
  `scripts/ee-builder-config.js` مباشرة إلى `enterprise/` داخل الحزمة بلا نسخ للمصدر العام.
  قائمة `packageFiles` في العقد هي allowlist تشغيلية؛ لا تدخل ملفات CI أو الاختبارات أو README.
- يحقن بناء Enterprise هوية مستقلة في metadata ويخرج إلى `dist/enterprise/`. الهوية لا تعتمد
  على نجاح الترخيص: فشل الوحدة يظهر كتشخيص Enterprise مع قدرات معطلة، لا كـCommunity صامت.
- ناشر Community مصفّر صراحةً ومحدث GitHub العام معطل دفاعياً في Enterprise. workflow الخاص يفحص
  `app.asar` ويولد provenance ببصمات SHA-256 وSHA دقيق للمستودعين قبل رفع Artifact الخاص.
- التحقق الدائم: بناء مجتمعي + حذف `enterprise/` ⇒ يعمل كاملاً (معيار §1).

## 7) القواعد الإلزامية (مكمّلة لقواعد CLAUDE.md)

1. **النواة لا تعرف Enterprise**: لا `require` صريح من `core → enterprise`؛ فقط عبر المُحمِّل الشرطي.
2. **صفر تكرار**: منطق مشترك يعيش في النواة. Enterprise يمتدّ لا ينسخ.
3. **النواة تعمل وحدها دائماً**: حذف `enterprise/` لا يكسر شيئاً (اختبار قبول دائم).
4. **الترخيص واضح**: كل ملف في `enterprise/` تحت الرخصة التجارية، لا FSL-1.1-MIT.
5. **العربية أولاً + الأمان أولاً**: قواعد CLAUDE.md تنطبق على الطبقتين بلا استثناء.
6. **نقاط الربط موثّقة**: أي نقطة ربط جديدة تُضاف هنا وفي CLAUDE.md.
