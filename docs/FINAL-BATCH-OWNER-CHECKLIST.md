# ما يحتاج المالك — الدفعة النهائية

**الحالة: جاهزة — لم يبدأ القبول اليدوي.** آخر تحديث: 2026-09-09.

نجحت بوابةv15 السابقة `103/103` برمز0 بعد إعادة واحدة. بعد إصلاح الرسالة الذي كشفته التجربة الحية نجح طقم الجوال9/9 وبناءv16 المطابق175/175 والتحقق الحي اللاحق؛ لم يُعد الكامل بعده. الحزمة الحالية تعمل معLAN؛ [أدلة البوابة](FINAL-BATCH-TEST-EVIDENCE.md). هذه ورقة للمتبقي البشري ومتطلبات الإعداد اللاحق. الربط الحالي برمز شخصي `PAT`، وOAuth العام غير مكتمل؛ إعداده لا يمنع قبول دفعة PAT الحالية.

اكتملت دورة الجوال البرمجية بطلب المالك، فلا تُضاف إلى أفعاله اليدوية المتبقية. [النتيجة](MOBILE-LIVE-20260909-EVIDENCE.md) تفصل نجاح المعاينة عن حدود الهاتف الفعلي وشهادةLAN والبيانات الخلوية وPush غير المقيسة.

## 1. يد المالك في الجلسة الحالية فقط

المرجع التنفيذي هو [جلسة القبول النهائية](acceptance-final-batch.md): الطلبات الحرفية ومعايير الصواب والفشل واللقطات هناك. تبقى النقاط `11–14` في `project-a` ومحادثة Codex نفسها؛ تستخرج الأدوات معرّفات الموارد، فلا يعيد المالك كتابتها.

| النقطة | ما يحتاج يد المالك | نقطة الحكم |
|---|---|---|
| 11 — Netlify | الدخول إلى حسابه عند الحاجة، وإدخال PAT في حقل اللوحة السري، واختيار موقع تجريبي واختبار الخدمة ثم إرسال طلب القراءة الجاهز | تطابق الحساب والموقع مع `inspect` و`list_deploys` وظهور استعمال المحرك الفعلي |
| 12 — رفض البناء | تفعيل الكتابة للموقع التجريبي، وإرسال الطلب الجاهز ثم **رفض** بطاقة الإذن | وضوح أثر النشر وظهور الرفض؛ يتولى القائد إثبات عدم خروج طلب بناء |
| 13 — Supabase | الدخول إلى حسابه عند الحاجة، وإدخال PAT في الحقل السري، واختيار مشروع تجريبي ثم إرسال طلب القراءة | تطابق `inspect` و`list_tables` مع المشروع؛ قائمة جداول فارغة مقبولة |
| 14 — الفصل | فصل Netlify وSupabase من اللوحة ثم إرسال طلب التحقق في المحادثة نفسها | ظهور الفصل ونتيجتي `not_connected` من الأدوات |

يلزم مورد تجريبي متاح في كل خدمة؛ لا يُفترض وجود حساب أو مورد، ولا تُرسل الرموز في المحادثة أو اللقطات. يتولى القائد تجهيز الحزمة وLAN وHTTPS وPWA والتحقق منها على الحاسوب وتسجيل الأدلة، مع حفظ `project-a` و`project-b` و`profile` الحاليين. هذه أعمال تقنية مأذونة وليست قرارات منتجية جديدة.

نتائج GitHub المقبولة محفوظة؛ الخطوة 9 متجاوزة بطلب المالك و10 مؤجلة، وكلتاهما غير مجتازة. الجلسة لا تختبر كتابة GitHub أو بناء Netlify مقبولاً أو OAuth العام أو الاتصال الخلوي وWeb Push. [الحدود ونقطة الاستئناف](acceptance-connections.md).

## 2. ورقة متطلبات OAuth العام — إعداد لاحق

تنطلق من [خطة التوصيلات](CONNECTIONS-PLAN.md). الأسماء أدناه أسماء حقول ومتطلبات، وليست قيماً فعلية. لم تُفحص حسابات المالك أو تسجيلات تطبيقاته أثناء إعداد الورقة؛ يُستفاد من تسجيل صالح قائم إن وُجد. التحقق من المصادر الرسمية: 2026-09-09.

| الخدمة | التسجيل وهوية التطبيق | المعلومات غير السرية التي نجهزها أو نستخرجها | ما يتوقف عليه التنفيذ الحي |
|---|---|---|---|
| GitHub | `GitHub App` يملكه حساب سطر أو منظمة مخوّلة؛ من `Developer settings → GitHub Apps` مع تفعيل `Enable Device Flow` | الحساب المالك، اسم فريد، `Homepage URL`، الصلاحيات الدنيا ونطاق التثبيت، ثم `client_id`؛ وهو مختلف عن `App ID`. نجهز الصلاحيات وفق عمليات التوصيلة المعتمدة | يلزم تسجيل صالح وتثبيت/تفويض فعلي قبل قياس الدخول والموارد. Device Flow لا يحتاج `Callback URL`، ولا يحتاج `client_secret` لإصدار الرمز أو تجديد رمز صدر عبره. [التسجيل](https://docs.github.com/en/apps/creating-github-apps/registering-a-github-app/registering-a-github-app)، [Device Flow](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-a-user-access-token-for-a-github-app#using-the-device-flow-to-generate-a-user-access-token)، [التجديد](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/refreshing-user-access-tokens) |
| Netlify | تطبيق في `User settings → OAuth applications` تحت حساب يملك تسجيل سطر | هوية الحساب والتطبيق، `client key/client_id`، و`Redirect URI` نحدده تقنياً ونطابقه مع التسجيل قبل التنفيذ | التكامل العام يشترط OAuth. التوثيق يذكر `client key` و`client secret`؛ يلزم إثبات مسار المنح المناسب للتطبيق المكتبي وحماية السر، ثم التفويض الحي. لا يُفترض أن PAT أو مجرد تسجيل التطبيق يحققان ذلك. [المصادقة والتسجيل](https://docs.netlify.com/api-and-cli-guides/api-guides/get-started-with-api/#authentication)، [مرجع عنوان الرجوع](https://www.netlify.com/blog/2016/10/10/integrating-with-netlify-oauth2/) |
| Supabase | تطبيق `Management OAuth` من `Organization settings → OAuth Apps → Add application` في منظمة تملك تسجيل سطر | هوية المنظمة والتطبيق، `client_id`، و`redirect_uri` المطابق، ونطاقات API الدنيا التي نثبت ملاءمتها لعمليات القراءة؛ النطاقات تضبط عند إنشاء التطبيق | يلزم تسجيل/نشر تطبيق OAuth والتفويض الحي. تبادل الرمز يتطلب `client_secret` حتى مع PKCE؛ يجب تجهيز طريقة حمايته قبل التنفيذ. هذا المسار مختلف عن مصادقة MCP المستضاف. [التسجيل والتدفق](https://supabase.com/docs/guides/integrations/build-a-supabase-oauth-integration)، [النطاقات](https://supabase.com/docs/guides/integrations/build-a-supabase-oauth-integration/oauth-scopes) |

**عملنا التقني:** تجهيز الاسم والوصف والروابط من مواد المشروع، ومطابقة الصلاحيات وعناوين الرجوع، وتصميم التبادل والتجديد والإلغاء وربط النتيجة بمالك المشروع، والحراس واختبارات الرفض. لا نطلب من المالك اختيار بروتوكول أو حل مشكلة روتينية. لا تفترض هذه الورقة أن Grant بعينه مناسب لـNetlify لمجرد وجود مثال قديم له.

**ما يحتاج حساب المالك لاحقاً:** تثبيت الحساب أو المنظمة المالكة إذا لم تكن معلومة، والدخول أو النقرة الإدارية اللازمة لإتمام تسجيل أعددنا حقوله للمراجعة، ثم تفويض حساب ومورد تجريبيين. لا تُكتب قيم `client_secret` أو رموز المستخدم في هذه الورقة أو المحادثة. إذا كشف التصميم حاجة إلى استضافة أو تكلفة جديدة، نجهز مقترحاً محدداً قبل طلب اعتمادها؛ لم تُختر استضافة أو تُنشأ تكلفة أو تطبيقات أو backend بموجب هذه الورقة.

## 3. القرارات المحفوظة خارج الجلسة

- **OBS-144:** تأجيل المبدّل صريح؛ رفع التأجيل قرار مالك قبل استئناف تنفيذه. عزل توصيلات المشروع يبقى مطلوباً في الدفعة الحالية. [القرار](OBSERVATIONS.md#obs-144--مبدّل-المشاريع-في-نافذة-واحدة-مع-محادثات-مستقلة-للمشروع-نفسه).
- **OBS-146:** الأتمتة والتحكم من الجوال ضمن برو وتكاملهما معتمدة من حيث المنتج؛ لا نطلب إعادة اعتماد الفكرة. العقد التفصيلي وخطة التنفيذ عمل مستقل لم يكتمل، ولا يدخلان قبول PAT الحالي. [الملاحظة](OBSERVATIONS.md#obs-146--مهام-سطر-للأتمتة-في-برو-مع-إعادة-استخدام-التحكم-من-الجوال).
- **توسعات تحتاج قراراً منفصلاً عند طرحها:** إنشاء مهمة أو توجيه نص حر من الهاتف، والتشغيل والجهاز مغلق بما يلزمه من منفذ مستقل ونطاق وتكلفة. أما هوية `project/task/run/action` وحراسة الملكية والإقرارات فمسائل تصميم وتنفيذ نجهزها تقنياً ضمن العقد المأذون؛ ليست أسئلة لإعادة اعتماد المنتج.
