## 1) التحقق الحيّ المُثبِّت لآلية الأنماط (نُفِّذ في جلسة التخطيط)

اختبار Electron مصغّر بنفس إعدادات أمان «سطر» (contextIsolation + sandbox + لا
nodeIntegration) وصفحة بـ `style-src 'self'` صارمة (لا inline ولا هاشات):

| الاختبار | النتيجة |
|---|---|
| `adoptedStyleSheets` على المستند (`new CSSStyleSheet()` + `replaceSync`) | ✅ يعمل |
| `adoptedStyleSheets` على shadow root داخل Web Component | ✅ يعمل |
| وسم `<style>` داخل Shadow DOM | ⛔ **محجوب** بـ CSP (كما خشينا) |

**القرار المثبّت**: أنماط المكوّنات نص CSS في وحدات JS (قوالب حرفية) ⇒ `CSSStyleSheet`
⇒ `shadowRoot.adoptedStyleSheets`. ملفات JS الخارجية تغطيها `script-src 'self'` — **لا
هاشات جديدة إطلاقاً لكل مكوّن، ولا inline**. وسم `<style>` داخل Shadow DOM ممنوع (محجوب أصلاً).

ملاحظة مكمّلة: **متغيّرات CSS (Design Tokens) تعبر حدود Shadow DOM بالوراثة** — تبقى
في `:root` بالورقة الأساس، والمكوّنات تستهلك `var(--gold)` إلخ كما هي. الخط كذلك
(@font-face على مستوى المستند وfont-family بالوراثة).

## 2) القرارات المعمارية المقترحة

1. **صفر اعتماديات، صفر بنّاء**: Web Components أصلية + ES modules عادية من `src/ui/`
   — لا إطار ولا bundler (قاعدة CLAUDE.md 5 كما هي).
2. **آلية الأنماط**: adoptedStyleSheets (القسم 1). ورقة أساس عامة للمستند
   (`src/styles/base.css` عبر `<link>` — تغطيها `'self'`) للرموز (tokens) وبقايا
   الأنماط غير المفكّكة، وأوراق مشتركة كوحدات (مثل `panel.css.js` لأنماط اللوحات
   الجانبية المتكررة، و`diff.css.js` لبطاقات الفرق) تُدرج في مصفوفة
   adoptedStyleSheets لكل مكوّن مستهلك.
3. **Shadow DOM للمعزول، وبدونه للحسّاس**:
   - **بـ Shadow DOM**: اللوحات الجانبية والمنبثقات (جلسات/ملفات/git/مهارات/موصلات/
     سياق/وكلاء/عارض/بوابة/أذونات) — عزل أنماط حقيقي ومكسب التفكيك الأكبر.
   - **Custom element بلا Shadow DOM** (أنماطه تبقى في base.css): **الطرفية**
     (xterm.js يقيس ويلتقط أحداثاً على DOM المستند — إدخاله shadow مخاطرة معروفة
     بلا مكسب) و**المحادثة** (إعادة بناء innerHTML أثناء البث + حقن أزرار النسخ +
     بطاقات diff/وكلاء تُبنى من مسارات متعددة — العزل هنا خطر لا فائدة).
     قرار قابل للترقية لاحقاً إن ثبت النفع.
4. **المشتركات وحدات لا مكوّنات**: `buildDiff` (تستهلكه المحادثة + لوحة git + حفظ
   العارض) و`renderMD` (المحادثة + معاينة الجلسات) و`hlLine` (العارض) تُستخرج إلى
   `src/ui/lib/*.js` كدوال مصدَّرة تُنتج DOM — تُستدعى من أي مكوّن أو من القشرة.
5. **عقد المكوّن**: خصائص/سمات للداخل، `CustomEvent` (bubbles + composed) للخارج،
   وmethods عامة عند الحاجة (مثل `getActiveSkills()`). المكوّنات تستدعي
   `window.satr.*` مباشرة (preload هو حدّ الأمان — لا وسيط جديد). **حالة التطبيق**
   (cwd/engine/model/sessionId/busy) تبقى ملك القشرة حتى دفعة «المؤلّف» — المكوّنات
   تطلب التغيير بحدث والقشرة تقرّر (مثال: `session-resume` من لوحة الجلسات).
6. **جسر انتقالي مؤقت**: القشرة (السكربت الضخم) تبقى **سكربتاً كلاسيكياً خارجياً**
   (`src/ui/app.js` بلا type=module — يتفادى مفاجآت strict mode على 2950 سطراً).
   الوحدات المشتركة تُصدَّر ES exports **وتُعلَّق أيضاً على `window.SatrUI`** لتستهلكها
   القشرة — الجسر يُزال في الدفعة الأخيرة عند تحويل القشرة نفسها لوحدة.
   المكوّنات ذاتية التسجيل (`customElements.define`) تُحمَّل بوسوم
   `<script type="module" src>` — تنفيذها بعد القشرة (deferred) مقبول: القشرة تتفاعل
   بالأحداث لا بنداء مبكر (وعند الضرورة `customElements.whenDefined`).
7. **التسمية**: بادئة `satr-` (مثل `<satr-agents-panel>`)، ملف لكل مكوّن في
   `src/ui/components/`، aria-label تنتقل للمضيف، والاتجاه RTL بالوراثة (`:host`).

## 3) مصير `scripts/update-csp.js`

- **الدفعة ت-0** تنقل كتلتي `<style>` و`<script>` المضمّنتين إلى ملفات خارجية ⇒ لا
  كتل مضمّنة تُهَشّ. يُحدَّث update-csp.js ليتسامح مع **صفر كتل** (يُسقط الهاشات من
  التوجيه عندها) ويبقى:
  1. **المصدر الوحيد لقالب CSP** (التوجيهات) كما هو اليوم — أي توجيه جديد يُضاف فيه.
  2. **حارساً**: أي كتلة مضمّنة تعود مستقبلاً تُهَشّ تلقائياً كالسابق.
- يبقى في `prestart`/`predist` بلا تغيير. لا حاجة لتوجيهات CSP جديدة: الوحدات
  والورقة الخارجية تغطيها `'self'` القائمة.

## 6) سجلّ المخاطر والتحوطات

| الخطر | التحوّط |
|---|---|
| strict mode عند تحويل القشرة لوحدة | مؤجَّل للنهاية (ت-13) — حتى ذلك الحين كلاسيكي خارجي بلا تغيير دلالي (ت-0) |
| توقيت ترقية المكوّنات (modules مؤجَّلة التنفيذ) | القشرة تتفاعل بالأحداث؛ `customElements.whenDefined` عند نداء مبكر ضروري |
| `getElementById` عبر حدود shadow ينكسر | قائمة فحص لكل دفعة: grep لكل id منقول قبل الحذف — صفر إشارات متبقية في القشرة |
| xterm.js داخل shadow (قياسات/أحداث) | الطرفية بلا shadow أصلاً (قرار القسم 2/3) |
| إعادة بناء innerHTML أثناء البث داخل shadow | المحادثة بلا shadow أصلاً (قرار القسم 2/3) |
| ترتيب Escape العالمي (عارض ⇒ لوحة ⇒ …) | يبقى في القشرة كموجّه واحد يستدعي methods المكوّنات (`close()`) |
| تفلّت أنماط أثناء الانتقال (منطقة فُكّت وأنماطها بقيت في base.css) | كل دفعة تنقل CSS منطقتها معها — لا ازدواج |
| كسر عقد IPC | **محظور بالتعريف**: التفكيك واجهة خالصة — صفر تغيير في preload/main/الأحداث |

## 7) ما لا يتغيّر (حدود صلبة)

- كل عقود IPC والأحداث كما هي حرفياً (لا مساس بـ preload.js أو main.js أو المحرّكات).
- صفر اعتماديات وقت تشغيل للواجهة، لا بنّاء، لا إطار.
- CSP بلا inline (السمات المضمّنة محظورة كما كانت — CSSOM وaddEventListener فقط).
- العربية أولاً + قواعد الاتجاه المثبّتة (كود LTR داخل RTL، dir=auto للمختلط).
- تجميد الأوامر (لا أوامر `/` جديدة) — التفكيك لا يضيف ميزات، ينقل القائم فقط.
