### بوابة أول التشغيل + الأيقونة (المرحلة 6 — تلميع المنتج)

- **بوابة أول التشغيل (مانع إطلاق)**: تحجب المحادثة خلف `<satr-gate>` حتى يتوفر أحد
  المحركات الأصيلة الثلاثة (Claude Code/Codex/Kimi Code) جاهزاً، **أو** يوجد مزوّد REST
  له مفتاح API محفوظ. المفتاح المحفوظ يكفي للفتح؛ فلا يُشترط اشتراك Claude ولا تثبيت CLI.
  - IPC `satr:preflight({force?})` يحفظ الحقول القديمة `claude/node/npm` ويضيف حرفياً
    `{engines, keyProviders:[{name,label}], ready, readyEngines, preferred}`. `engines`
    للأصيلة الثلاثة فقط؛ و`keyProviders` مرتبة بترتيب سجل المحوّلات ولا تحمل قيمة مفتاح
    ولا حتى `keyName`. `ready` صحيح إن وجد أصيل جاهز أو مزوّد ذو مفتاح، و`preferred`
    أول أصيل جاهز ثم أول مزوّد ذي مفتاح. مصدر المفاتيح `keys.names()` (أسماء فقط).
  - الفحص الأول يستفيد من كاش نجاح `codex.accountStatus` ذي 90ث. زر «أعد الفحص» وحده
    يرسل `{force:true}` عبر `preload` المنقّى، فيتجاوز كاش الحساب ويلتقط تسجيل دخول تمّ
    بعد الإقلاع؛ `satr:codexStatus` يبقى بلا `force` لأنه تلميح تبديل لا فعل إعادة فحص.
    اكتشاف الثنائيات نفسه بالقوة، والفحوص متوازية وبمهلة حتى لا تتعلّق البوابة.
  - إن لم يجهز أصيل تعرض البوابة، أسفل خطوات التثبيت/الدخول، مسار «مفتاح API مجاني»:
    شرحاً للمبتدئ وروابط NVIDIA NIM وGroq (حساب بلا بطاقة)، ثم مزوّدي REST ذوي `keyName`
    والمجانيين أولاً، وحقل `password`. الحفظ يستعمل `satr:keySet` القائم المحصور بأسماء
    المزوّدين المسجّلين، يمسح الحقل فوراً، ثم يعيد الفحص. لا تعبر قيمة المفتاح أي رد ولا
    تظهر في الخطأ. وعند الفتح بمفتاح تصحح القشرة اختيار محرك أصيل غير جاهز إلى المزوّد.
  - **توافق الإصدار**: يستخرج semver من Claude ويقارنه بـ`CLAUDE_MIN_RECOMMENDED`
    (2.1.197 لـ Sonnet 5)؛ القديم يعرض إرشاد تحديث غير حاجب بلا تحديث تلقائي.
  - **للاختبار فقط**: `SATR_FORCE_NO_CLAUDE=1` و`SATR_FORCE_NO_CODEX=1` و
    `SATR_FORCE_NO_KIMI=1` و`SATR_FORCE_NO_KEYS=1` تحاكي غياب الأصيلة والمفاتيح
    دون إلغاء تثبيت أو حذف شيء؛ بلا أثر عادي.
- **الأيقونة وعلامة شريط المهام**: `build/icon.ico` (يولّدها `scripts/make-icon.js`). main.js يضبط
  `app.setAppUserModelId('ai.satr.app')` وأيقونة النافذة (دلالياً للتطوير؛ المثبّت يضمّن الأيقونة
  في الـ exe عبر `build.win.icon`). الملف خارج `files` فلا يُحزَم في asar — في الإنتاج تأتي
  الأيقونة من مورد الـ exe، وفي التطوير من الملف على القرص (الحارس `fs.existsSync`).
- **مؤجَّل للمرحلة 7**: التحديث التلقائي (electron-updater) — يحتاج مستودع GitHub عاماً وإصدارات
  (Releases) لا توجد بعد، فيُنفَّذ مع إطلاق المصدر المفتوح. ولوحة `/تكلفة` مُلغاة (تجميد الأوامر).
