# مقترح الدفعة ب — «المسار الموجّه» لغرفة العمليات (لاعتماد محمد قبل أي كود)

المرجع: `docs/OPS-ROOM-POLISH-SCOPE.md` — الدفعة ب (جواب الملاحظة 26: «لم أفهم الغرفة
وأنا مطوّرها»). هذا مقترح تصميم فقط؛ **لا يُكتب سطر كود قبل اعتماد هذا المستند**.

## 1. الفكرة في سطرين

السطح الحالي منظم حسب **نوع البيانات** (العمل/النتائج/السجل) فيتطلب من المستخدم معرفة
أين يسكن كل شيء. المقترح: تنظيمه حسب **رحلة المستخدم** — شريط خمس محطات ظاهر دائماً
(إعداد ← تنفيذ ← مراجعة ← تحقق ← دمج)، وتحته **بطاقة المحطة الحالية وحدها** بزر فعل
واحد كبير. المرجع الإيجابي المتفق عليه: بطاقة الحلقة المحدودة («الدورة 1/3 · نجحت ·
الكلفة · سبب التوقف + ماذا بعده»).

## 2. ما لا يتغيّر (حدود صلبة)

- `ops-room-state.js` (reducer + `deriveOpsRoomState`) يبقى **مصدر الحقيقة الوحيد** —
  التغيير عرضٌ خالص في `ops-room.js`.
- صفر تغيير في IPC أو preload أو أحداث `satr:event` أو أي عقد أمني (بوابات الدمج
  والتأكيدات الصريحة كما هي حرفياً).
- بعد أ‑1 صار العقد: **لا حالة طرفية بلا فعل تالٍ** (`nextAction.action` دائماً موجود
  حين يملك المستخدم خطوة) — الشريط الجديد يستهلك هذا مباشرة.
- الحلقة المحدودة تبقى بطاقتها كما هي (المرجع الإيجابي لا يُعاد بناؤه)؛ تُعرض مكان
  بطاقة المحطة حين تملك الحلقة الفريق.

## 3. الشريط التفاعلي — خمس محطات وحالاتها المشتقة

```
[① إعداد] ── [② تنفيذ] ── [③ مراجعة] ── [④ تحقق] ── [⑤ دمج]        (المزيد ⌄)
   ✓ منجزة      ✓ منجزة      ● حالية       ○ لاحقة      ○ لاحقة
```

كل محطة تُشتق حالتها من `deriveOpsRoomState` القائمة — **جدول الاشتقاق**:

| المحطة | منجزة ✓ | حالية ● | تنبيه ⚠ |
|---|---|---|---|
| إعداد | وُجد فريق (أي team) | لا فريق / `canStart` بعد نهاية | — |
| تنفيذ | `team.state === 'completed'` | `teamActive` | فشل/مهلة/تعارض/تنظيف |
| مراجعة | `reviewApproved` | `reviewActive` أو `canReview` | حكم غير موافق / مراجعة لم تكتمل |
| تحقق | `verificationPassed` | `verificationActive` أو `canPrepareVerification` أو `canRunVerification` | تحقق فاشل |
| دمج | `team.merged` | `canMerge` (+ «شاهدها تعمل» هنا) | فشل دمج (رمز الخطأ) |

- **النقر على محطة منجزة يعرض نتيجتها** في مساحة البطاقة (بلا مغادرة المسار): إعداد ⇒
  المهام والملكيات كما بدأت؛ تنفيذ ⇒ بطاقات العوامل والفروقات؛ مراجعة ⇒ الأحكام
  والتقرير المدموج؛ تحقق ⇒ صفوف الفحوص؛ دمج ⇒ خلاصة التطبيق + «ابدأ مهمة جديدة».
- النقر على محطة لاحقة لا يفعل شيئاً سوى إظهار «ما ينقص» (نص بوابةٍ من الحالة الفعلية
  — يتكامل مع البند 13 من أ‑2).
- المؤشر الوصفي القديم (`stage-indicator` الرباعي) يُستبدل بهذا الشريط — لا سطحان
  يحكيان الرحلة مرتين.

## 4. بطاقة المحطة الحالية — العقد

مكوّنات ثابتة بنمط بطاقة الحلقة:
1. **سطر الحالة**: ماذا يجري الآن بلغة بشرية (من خريطة تعريب lifecycle الموحدة — أ‑2).
2. **جسم مختصر**: أرقام المحطة فقط (عدد العوامل وتقدمها / الأحكام 2 من 2 / الفحوص
   3 من 3 / ملفات الأثر و±).
3. **زر فعل واحد كبير** = `nextAction` حرفياً (ابدأ التنفيذ / ابدأ المراجعة / ثبّت
   التحقق / شغّل الاختبارات / ادمج الأثر / ابدأ مهمة جديدة).
4. **إيقاف** ظاهر بجانب أي جريان (`canStop`)، و«مدّد المهلة» عند تحذير العدّاد — لا
   يختبئان في قائمة (عقد قائم يُحفظ).
5. **إرشاد التعافي** عند الفشل (رمز الخطأ المترجم + الخطوة — يرث إصلاحات أ‑1 البند 15).

## 5. أين تذهب الأقسام القائمة

- **العصف والتقسيم الاقتراحي**: داخل محطة «إعداد» (زران ثانويان في بطاقتها) — هما
  أدوات تجهيز المهمة أصلاً.
- **القرارات والنقاش والتاريخ والسجل**: خلف زر «المزيد ⌄» في طرف الشريط — درج واحد
  بقائمة بسيطة (سجل الغرفة / القرارات / التاريخ والاستعادة / إعداد التحقق). التاريخ
  يبقى افتراضي ما بعد إعادة التشغيل (بند 17 من أ‑2).
- **بطاقات inline في الدردشة** (`showOpsEvent`) بلا تغيير.

## 6. سيناريوهات المحطات الخمس (نصية — كما سيراها محمد)

**س1 — الدخول لأول مرة (إعداد):** شريط المحطات كله ○ والمحطة ① حالية. البطاقة:
«حدّد مهمة العامل وملكية ملفاته» + النموذج النظيف (عامل واحد افتراضياً) + زرا «🧠
عصف» و«🧩 اقترح تقسيماً» الثانويان + زر كبير «ابدأ التنفيذ». لا شيء آخر على الشاشة.

**س2 — تنفيذ جارٍ:** ① ✓ و② ● نابضة. البطاقة: «عامل 1 ينفّذ داخل نسخة معزولة —
آخر نشاط: تعديل src/app.js قبل 12ث» + شريط الوقت المتبقي + «⏹ إيقاف». عند انتهاء
المهلة أو الفشل: ② ⚠ والبطاقة تعرض السبب المترجم + إرشاد التعافي + «ابدأ فريقاً
جديداً» (يرث النموذج — عقد أ‑1).

**س3 — مراجعة:** ② ✓ و③ ●. البطاقة قبل البدء: «اكتمل التنفيذ وأُنتج أثر (5 ملفات،
+120 −34) — الخطوة التالية مراجعتان مستقلتان» + «ابدأ المراجعة». أثناء الجريان: حالة
كل محرك وزواياه. بعد الأحكام: «وافق المراجعان ✓» أو «طلب Codex تعديلات ⚠» + التقرير
المدموج + «🔧 أصلح بالملاحظات» (فقط حين توجد بنود — عقد أ‑1). مراجعة أوقفها المستخدم:
«أوقفتها قبل اكتمال الأحكام» + «أعد المراجعة» (عقد أ‑1 البند 28).

**س4 — تحقق:** ③ ✓ و④ ●. البطاقة: أوامر `verify.json` المثبتة من HEAD حرفياً +
«ثبّت التحقق» ثم «شغّل الاختبارات» + النتائج صفاً صفاً (✓/✗ + المدة). بعد النجاح يظهر
«🖥 شاهدها تعمل» في البطاقة نفسها.

**س5 — دمج وما بعده:** ④ ✓ و⑤ ●. البطاقة: «وافقت المراجعات ونجح التحقق — سيُدمج
ملفان (+120 −34) على شجرة العمل بلا commit» + «ادمج الأثر» (تأكيد صريح كما هو). بعد
النجاح: الشريط كله ✓ والبطاقة «طُبّق الأثر — راجع التغييرات والتزم بها متى شئت» +
«ابدأ مهمة جديدة» بنموذج نظيف (عقد أ‑1 البندان 24 و22).

**س6 — الحلقة المحدودة:** حين تعمل حلقة، بطاقة الحلقة القائمة **هي** بطاقة المحطة
(تملأ ② و③ و④ داخلياً كما اليوم)، والشريط يعكس حالتها؛ بعد التسليم يعود المسار
العادي من محطة ③.

## 7. خطة التنفيذ التدريجية (بعد الاعتماد — توزيع ثلاثي)

1. **مرحلة ب‑1**: الشريط الجديد + بطاقة المحطة فوق البنية القائمة، والأقسام الثلاثة
   تبقى تعمل خلف «المزيد» (لا حذف — تحويل تدريجي). reducer يكسب دالة نقية واحدة
   `deriveStations(state)` (اشتقاق عرض فقط، تُختبر في test:opsroom-ui).
2. **مرحلة ب‑2**: نقل محتوى النتائج/الفروقات/الأحكام إلى عرض المحطات المنجزة، وإخفاء
   التبويبات المتوازية.
3. **مرحلة ب‑3**: تنظيف، مشاهد ui:audit جديدة (محطة لكل حالة)، توسعة
   test:opsroom-ui-live، وتحديث دليل satr-guide.
- التوزيع المقترح: كودكس = الشريط والبطاقة (ops-room.js)؛ كيمي = عروض المحطات المنجزة؛
  أوبس/القائد = `deriveStations` واختباراتها + المشاهد. (يُقسم نهائياً بعد الاعتماد.)

## 8. أسئلة مفتوحة لقرار محمد

1. **موضع العصف**: داخل محطة الإعداد (المقترح) أم يبقى مدخلاً مستقلاً في «المزيد»؟
2. **الشريط في الوضع الضيق (drawer)**: تكديس عمودي للمحطات (المقترح) أم شريط أفقي
   قابل للتمرير؟
3. **هل تُحذف التبويبات القديمة نهائياً في ب‑2** أم تبقى «عرضاً متقدماً» خلف مفتاح
   حتى جولة ج؟ (المقترح: حذف — سطحان لنفس الحقيقة يعيدان مشكلة الملاحظة 26.)
4. اعتماد نصوص السيناريوهات أعلاه كما هي أم تعديل صياغات؟
