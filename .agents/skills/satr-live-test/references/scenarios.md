# سيناريوهات الاختبار الحي

اقرأ السيناريو المرتبط بالادعاء فقط. هذه قوالب تجربة، وليست أوامر تُنشئ تلقائياً
المحرك أو الاقتران أو أدوات القيادة. راجع توافر تلك المتطلبات قبل التنفيذ.
المنهج مستخلص من [دليل تجربة الجوال الحية](../../../../docs/MOBILE-LIVE-20260909-EVIDENCE.md)؛
نتائج تلك التجربة لا تُنقل إلى نسخة جديدة.

## قيادة النافذة الرئيسية

أطلق التجربة بـ`launch <id> --debug` ثم انتظر `LIVE_TEST_READY`.
الوحدة `scripts/lib/live-test-client.js` تعرض `connectMain(repoRoot, id)`؛
تقرأ بيان التجربة وحالتها، وتطابق الملف الشخصي و`windowId/mainUrl/debugPort`،
ثم تنتقي صفحة رئيسية واحدة بعنوانها المحدد من CDP المحلي.
لا تمرّر منفذاً أو URL من عندك. عند `ambiguous_target` أو `profile_mismatch`
أوقف القيادة؛ لا تختَر أول نافذة كي يمرّ الاتصال.
قد يظهر `debug_unavailable` إذا لم يُفعّل `--debug` أو لم يجهز المنفذ بعد؛
اقرأ الحالة والسجل ضمن مهلة التجهيز قبل تقرير أن القدرة غائبة.

مثال قراءة محدود داخل سائق Node؛ مرّر جذر المستودع المطلق ثم معرّف التجربة كوسيطين:

```javascript
'use strict';
const path = require('path');
const repoRoot = process.argv[2];
const id = process.argv[3];
const { connectMain } = require(path.join(repoRoot, 'scripts/lib/live-test-client'));
async function main() {
  const client = await connectMain(repoRoot, id);
  try {
    const title = await client.evaluate('document.title');
    console.log(JSON.stringify({ title }));
  } finally {
    client.close();
  }
}
main().catch(error => {
  console.error(error.code || 'live_driver_failed');
  process.exitCode = 1;
});
```

احفظ السائق داخل موارد التجربة وشغّله بالطرفية المرئية.
`evaluate` ينفّذ تعبيراً في renderer الرئيسي، ينتظر الـPromise ويعيد القيمة القابلة للتسلسل؛
استخدمه لقراءة DOM وقيادة عناصر الواجهة الفعلية ضمن التفويض.
لا يوفّر `browser_snapshot` أو `browser_readability` أو لقطة شاشة تلقائياً،
ولا يتيح قيادة مربع تأكيد النظام. عند الحاجة إليها جهّز المسبار المناسب وسمِّ حدوده.
`close()` يفصل اتصال CDP فقط؛ إغلاق التطبيق يتم بأمر `live-test.js close <id>`.
يتطلب العميل Node يوفر `WebSocket`؛ `websocket_unavailable` يعلن نقص هذه القدرة،
ولا يجيز الاتصال بنسخة أخرى أو إضافة اعتماديات بلا مبرر.
الاتصال لا يهيئ مصادقة المحرك؛ أكمل الإعداد الصريح داخل البيئة المعزولة قبل طلب مهام حقيقية.

## سجل المحاولة

اكتب قبل الفعل: معرّف التجربة والسيناريو، المصدر أو الحزمة وبصمتها المتاحة،
المحرك والنموذج الفعليان، ميزانية الوقت والتكلفة، معيار الصواب والفشل.
احفظ بعده معرّف الطلب والدور باسم بديل غير سري، نطاق الزمن، الأثر الفعلي،
النص المرئي، رابط الدليل، ومقطع التسجيل إن وُجد.
ميّز بين حدث شوهد، ونتيجة استُدل عليها من مسار الكود، وحالة لم تُقَس.
بصمة الإقلاع الحالية تشمل `electron/main.js` و`electron/promocapture.js` و
`electron/preload.js` و`src/index.html` و`src/ui/components/preview-panel.js` فقط؛
لا تسمّها بصمة كل المصدر أو الحزمة. وثّق ملفات الادعاء الأخرى عند الحاجة.
تسجيل حدث قبل اكتمال عملية الإرسال لا يثبت وصوله.

## 1. الرفض والسماح وأثرهما — `deny-allow`

**الادعاء:** قرار الإذن الذي اتخذه المستخدم أو السائق المفوّض وصل إلى الطلب الجاري،
فمنع الأثر عند الرفض وأحدث الأثر المحدد عند السماح.

**التهيئة:** استخدم مجلد عمل داخل التجربة، واسمَي ملف جديدين خاصين بالمحاولة،
ومحتوى علامة معلوم. أثبت غيابهما قبل بدء الطلب. شغّل محركاً حقيقياً بعد إعداده المصرح،
بوضع أذونات يعرض القرار المراد اختباره. لا تعتمد قبولاً محفوظاً من دور سابق.
إن كان الادعاء متعلقاً بالهاتف، جهّز اقتران التجربة وعزل تخزينها دون تغيير حارس الإنتاج.

1. اطلب عبر مؤلف الإنتاج إجراءً واحداً ينشئ ملف الرفض. طابق بطاقة الإذن مع الأمر والطلب الجاريين.
   **الصواب:** تظهر البطاقة قبل حدوث الأثر. **الفشل:** يوجد الملف قبل القرار أو لا يمكن ربط البطاقة بالطلب.
2. انقر الرفض من السطح محل الادعاء، ثم انتظر دليل معالجة القرار وإنهاء المحاولة ضمن الميزانية.
   **الصواب:** يعالج الإنتاج رفض الطلب نفسه ويبقى الملف غائباً.
   **الفشل:** يظهر الملف أو يُنسب قرار طلب آخر إلى هذه المحاولة.
3. ابدأ طلباً جديداً ينشئ ملف السماح الآخر، وطابق بطاقته، ثم اسمح.
   **الصواب:** يصل قبول الطلب الجاري ويظهر الملف بالمحتوى المحدد حرفياً.
   **الفشل:** نجاح شكلي في البطاقة بلا أثر، أو محتوى مختلف، أو ملف سابق أعيد استخدامه.

افحص الملفات من خارج جواب المحرك؛ لا يكفي قوله إنه أنشأ الملف.
في مسار الهاتف يكون `mobile_decision` الموافق للطلب دليلاً أقوى من نقرة مسجلة؛
تأكد من دلالة الحدث في النسخة المستخدمة ولا تخترع حقولاً غير متاحة.
غياب الملف وحده لا يثبت الرفض إن تعذر الطلب أصلاً، والنقرة وحدها لا تثبت وصول القرار.
أي محاولة أنشأت الملف دون قرار مطابق تحفظ كفشل أو محاولة غير صالحة،
ولا تستعمل ملفها خط أساس لمحاولة الرفض التالية.

**حدود النتيجة:** إثبات رفض أو سماح واحد لا يغطي كل أنواع الأدوات أو أوضاع الأذونات.
المحاكاة المنفصلة مفيدة لحارس القطع، لكن يجب تسميتها محاكاة إذا استُخدمت.

## 2. إيقاف A وبدء B في الجذر نفسه — `stop-next-run`

**الادعاء:** ينتهي الدور A ثم يبدأ دور B في المشروع نفسه، وتعرض الواجهة حالة B
دون إبقاء رسالة انتهاء A. حراسة وصول رسالة قديمة متأخرة ادعاء مستقل.

**التهيئة:** سجّل الجذر المطلق ومعرّف الدور A، واطلب عملاً محدداً يتيح إيقافه.
اجعل الانتظار محدوداً وغير مدمّر؛ لا تنشئ عملاً مفتوح النهاية.
سجّل ملكية عملية المحرك إن كنت ستدّعي خروجها: `PID` ووقت الإنشاء والأصل عند توافره،
فالرقم وحده قد يعاد استخدامه.

1. أثناء A اطلب الإيقاف من واجهة الإنتاج وسجّل الطلب.
   **الصواب:** يصل إقرار الإيقاف المطابق للدور والطلب بعد اكتمال بوابة الإيقاف الفعلية،
   وتظهر رسالة الحالة المقابلة. **الفشل:** الإقرار قديم أو لدور آخر أو مجرد نقرة.
2. افحص انتهاء العملية التي رصدتها إن كان خروجها جزءاً من الادعاء.
   **الصواب:** يغيب مثيل العملية المحدد بعد الإيقاف.
   **الفشل:** يبقى المثيل حياً أو لا يمكن تمييزه من عملية أخرى.
3. في الجذر نفسه ابدأ B من المؤلف الفعلي، وسجّل خط أساس بعد نهاية A.
   **الصواب:** يصل إطار جديد بعد هذا الخط بمعرّف دور مختلف،
   وتنتقل الحالة المرئية إلى B وتزول رسالة انتهاء A.
   **الفشل:** تُقرأ حالة قديمة أو يبقى نص A رغم وصول حالة B.
4. إن كان الادعاء يشمل المهام، اطلب من محرك يدعمها تحديثات مهام حقيقية.
   **الصواب:** تصل `task_update` تخص B وتتغير العدادات والنص كما تتطلب تلك الأحداث.
   **الفشل:** تُحتسب `2/2` قديمة أو تُنسب مهمة محرك آخر إلى B.

لا تستعمل `proc_done` وحده لإثبات اكتمال `run.done`.
إن استدللت على الأخير من إقرار مسار ينتظره في الكود، سمِّه استدلالاً ووثّق البوابة.
خروج عملية واحدة لا يثبت خروج كل العمليات الفرعية منفردة.

**فصل حارس الرسائل القديمة:** نجاح A ثم B حياً لا يثبت رفض رسالة A المتأخرة
إذا لم تصل رسالة كهذه في التجربة. اختبر التداخل بحارس مستقل وزرع فعلي وفق عرف العضّة،
مع عدّ الأصل والمتحوّر وفشل الحارس واستعادة بايتات ما قبل الزرع.
لا تحقن الرسالة في السيناريو ثم تصفه بأنه محرك حقيقي أنتجها.
أبقِ نتيجة الحارس ونتيجة الانتقال الحي منفصلتين في التقرير.

## 3. إعادة التحميل واستعادة الحالة — `reload-state`

**الادعاء:** يعيد السطح المحدد تحميل صفحته ويستعيد الحالة التي صُمم لحفظها.
هذه تجربة إعادة تحميل؛ إثبات التعافي من انهيار أو انقطاع طاقة يحتاج سيناريو آخر.

**التهيئة:** حدّد الصفحة: واجهة Satr الرئيسية أو PWA أو صفحة معاينة معينة.
احفظ الحالة المتوقعة قبل التحميل من حقول غير سرية، وعدّاداً أو معرّفاً بديلاً عند الحاجة.
لـPWA تحقق من وجود اقتران التجربة ومخزنها المعزول؛ لا تطبع مفاتيحها أو رمز الاقتران.
حدّد أيضاً مالك المسجّل: `MediaRecorder` يعمل داخل قشرة سطر الرئيسية،
فتفقده إعادة تحميلها ولا يثبت التسجيل مقطعاً متصلاً عبر إعادة التحميل أو الانهيار.
إن كان السطح هو القشرة الرئيسية، أوقف المقطع وتحقق من حفظه قبل الخطوة 2،
واختبر إعادة التحميل دون تسجيل مستمر؛ أو التقط ما قبلها وما بعدها بمقطعين منفصلين
إذا توفر إذن المقطع الجديد. لا تعتمد مقطعاً انتهى إيقافه بـ`download_timeout`.
أما إعادة تحميل المعاينة أو PWA المعروضة داخلها فتبقي القشرة والمسجّل قائمين،
ويمكن تصويرها دون أن يعني ذلك اختبار إعادة تحميل القشرة نفسها.

1. اقرأ الحالة السابقة من DOM ومسار الحالة الفعلي، واحفظ الحد الأدنى اللازم للمقارنة.
   **الصواب:** توجد حالة جديدة معلومة تخص التجربة. **الفشل:** الحالة مجهولة أو خاصة بالمالك.
2. أعد تحميل الصفحة المحددة عبر فعلها الطبيعي، دون قتل العملية أو مسح التخزين.
   **الصواب:** تُعاد الصفحة ويتصل مسار الإنتاج. **الفشل:** تعطل التحميل أو فقدت الحالة المتوقعة.
3. اقرأ الحالة المستعادة من جديد، وقارنها بما قبل التحميل.
   **الصواب:** تُستعاد الحقول المقصودة ويعمل الإجراء التالي من دون إعداد غير متوقع.
   **الفشل:** يُطلب اقتران جديد خلاف العقد، أو يعاد استعمال عداد محظور، أو يظهر نص قديم.

في PWA قارِن هوية الجهاز داخلياً واحفظ نتيجة التطابق فقط متى كفت.
إن قِست سقف حجز عداد الإرسال، سمِّه سقف الحجز؛ ارتفاعه ليس عدد الرسائل المرسلة.
اختبر الطلب التالي إذا كان الادعاء يتجاوز مجرد ظهور الحالة.
لا تمدّد النتيجة إلى هاتف فعلي أو شهادة LAN أو relay أو Push إن لم تُختبر.

## صيغة التسليم

لكل ادعاء اكتب النتيجة مع دليلها وحدودها، مثل:
«عولج رفض الطلب الحالي وبقي الملف الجديد غائباً؛ تقرير المحاولة ومقطعها مرفقان.
لم يُختبر قبول دائم أو نوع أداة آخر».
إن كشف الأثر نجاحاً وكشف النص عيباً فاحفظ النتيجتين؛ لا تجمعهما في نجاح شامل.
يجب أن يظل الفشل الأول قابلاً للمراجعة بعد الإصلاح وإعادة المحاولة.
